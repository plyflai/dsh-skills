# _template

> 这是骨架，不是技能。复制成 `skills/<你的技能名>/` 并改写下面每一节。

## 激活标识

进入 skill 时输出：`🧩 <你的技能名> 已激活`

## 触发（何时加载）

写清**可观察的触发条件**，不要写「当用户需要帮助时」这类无法判定的条件。判断标准是：agent 读到这一节后，能明确回答「我现在是否处于这种情况」。

- 触发条件一：……
- 触发条件二：……

不应触发（加载后无动作，直接继续）：

- ……（说明相邻但**不属于**本技能职责的情况，避免技能越界干预）

## 默认目标

1. **<动作一>**：……（具体到可执行，不要写「理解用户意图」这类无法验收的话）
2. **<动作二>**：……
3. **<停止>**：……（写清什么情况下必须停下并交还用户）

## 读取顺序

1. [example-check.md](references/example-check.md) — 示例 reference 文件，把细节写在这里而不是堆进 SKILL.md
2. 需要确定性结果时运行 `scripts/<你的脚本>.mjs`

## 硬规则

- ⛔ 不要替用户拍板：存在真实取舍时提出选项并附推荐理由，决定权留给用户。
- ⛔ 不要伪造执行结果：任何动作的成败以实际返回为准。
- ✅ 不确定时显式说明「未验证」，不要把推测写成结论。
- ✅ 只缺一个只有用户才能确认的事实时直接问；能从材料或工具查到的先自己查。

## 写完之后

1. `name` 必须改成目录名，且只含小写字母、数字、连字符。
2. `description` 决定 agent 何时加载本技能，务必写「什么时候用」，不是「它是什么」。
3. 跑 `./scripts/validate.sh`。
4. 更新根 `README.md` 的技能清单表格。
