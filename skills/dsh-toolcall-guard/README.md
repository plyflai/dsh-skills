# dsh-toolcall-guard

当模型把工具调用输出成 `<tool_call>` 伪 XML **文本块**（而不是原生 function call，因此永远不会被执行）导致会话卡死时，按需加载本技能，引导模型自己恢复：解析块 → 原生重发 → 停止重复 → 继续原任务。

**按需加载，零常驻 token 成本**：它不挂在任何 hook 上，未命中触发条件时不进入上下文。

## 触发 / 不触发

触发（加载即按 [recovery-protocol.md](references/recovery-protocol.md) 行动）：

- 模型最近的输出里有 `<tool_call>` / `<function=...>` / `<parameter=...>` 文本块，而对应工具从未执行；
- 模型连续重复同一失败调用 ≥ 2 次；
- 用户直接指出「工具没执行 / 会话卡住 / 别再用 XML 块」。

不触发（加载后无动作，直接继续）：

- 工具调用全部是正常的原生 function call；
- 与调用格式无关的卡死（权限拒绝、参数语义、网络错误等）——那是通用调试，不是本技能职责；
- 解析与工具调用无关的任意 XML 文本。

## 它做什么

1. **自检**：看最近 1-3 条 assistant 输出，定位最后一个未执行的 `<tool_call>` 块。
2. **解析**：按 [parsing-rules.md](references/parsing-rules.md) 提取 function 名与参数；需要确定性结果时运行 `node scripts/parse-toolcall.mjs`（stdin 进，JSON 出）。
3. **重发**：工具在当前工具列表中 → 立即用**原生 function call** 重发，同名字同参数，恰好一次。
4. **拒绝**：工具不在列表或名字非法 → 不伪造调用，展示解析结果并请用户指示。
5. **停止**：同一块在历史中已有执行结果 → 直接继续，不再重复调用。

## 边界

- **没有 host 侧代执行能力**。一切调用由模型自己以原生 function call 发起，权限与 guard 照常生效 —— 技能是行为指引，不是强制钩子。
- 只修「格式错误导致未执行」这一种卡死。
- 依赖模型加载后正确执行引导；模型已完全失控时仍可能需要人工介入。

## 失败模式

| 场景 | 行为 |
| --- | --- |
| 解析失败（块内无合法 `<function=...>`） | 不猜测、不执行，展示原文请用户确认 |
| 工具不在当前工具列表 | 不伪造调用，报告解析结果请求指示 |
| 原生调用报错 | 按错误修正后重试一次；再失败停止并报告 |
| 同一块已处理过 | 静默继续，不重复注入提示 |

## 安装

```bash
../../scripts/install.sh dsh-toolcall-guard --target ~/.dsh/skills
```

`~/.dsh/skills` 是 DSH skill-filesystem 的用户根目录，watch 默认开启：软链接就位后下一个模型 step 即进入技能目录，无需重启。

## 测试

```bash
node --test tests/parse-toolcall.test.mjs
```

8 个用例覆盖解析脚本：单块、多块（后者胜）、未闭合块、多行与 Unicode 值、块内未知标签忽略等。

## 设计说明

`SKILL.md` 只放入口、触发条件与硬规则；解析规则与完整恢复流程分别在 `references/` 下的两个文件里，只在需要时读取。脚本只做确定性解析，恢复动作仍由模型发起——这是刻意的：技能不该在用户不知情时替他执行工具调用。
