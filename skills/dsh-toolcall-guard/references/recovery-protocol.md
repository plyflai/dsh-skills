# 恢复流程：从 XML 文本块卡死状态回到原生调用

完整恢复协议。按序执行；任一步失败按「失败处理」节收敛，不无限重试。

## 0. 自检

- 查看最近 1-3 条 assistant 输出，找 `<tool_call>` 文本块；
- 判定对应工具是否已执行：查看其后是否已有该工具的调用/结果记录。
- 已执行 → 直接回原任务（本技能结束，见「停止重复」）。
- 未执行 → 进入解析。

## 1. 解析

- 按 [parsing-rules.md](parsing-rules.md) 提取函数名与参数；
- 解析失败（无合法 `<function=...>`）→ 向用户展示原文，请求确认意图，不猜测。

## 2. 重发决策

- 工具名在**当前工具列表**中 → 重发路径；
- 不在列表中 → 拒绝路径：
  - 不伪造调用、不编造参数；
  - 向用户说明：解析到的工具名、参数、以及它不在当前可用工具中，请求指示。

## 3. 重发（恰好一次）

- 用**原生 function call** 调用同一工具，参数用解析结果；
- 数字/布尔等文本值按工具 schema 的正确类型转换后传入；
- 调用结果以返回为准：成功 → 回原任务；失败 → 看「失败处理」。

## 4. 停止重复

- 同一块（同函数名+同参数）已重发过一次且已有结果 → **不再重发**；
- 若历史中已存在相同调用 2 次以上仍失败 → 停止，向用户报告：已尝试 N 次、失败原因、建议下一步；
- 恢复后不再输出任何 `<tool_call>` 文本块。

## 5. 稳定文案（模型可见，勿改词）

需要向用户说明或注入纠正时使用（双语）：

> Tool call format: this harness only executes NATIVE function calls. Never emit `<tool_call>`, `<function=...>` or `<parameter=...>` XML text blocks — they are NOT parsed or executed. If you need a tool, issue a native function call directly.
> 工具调用格式：本环境只执行原生函数调用。禁止输出 `<tool_call>`/`<function=>`/`<parameter=>` 之类 XML 文本块——它们不会被解析执行。需要工具时请直接发出原生函数调用。

## 失败处理

| 失败 | 动作 |
|---|---|
| 解析失败 | 展示原文，请用户确认，不执行 |
| 工具不在列表 | 说明工具名+参数，请求指示，不伪造 |
| 原生调用报错（权限/参数/网络） | 以错误原文为据修正参数后重试**一次**；再失败停止并报告 |
| 同一块已处理 | 静默继续，不再注入任何提示 |
| 用户已指出问题但拒绝重发 | 停下，等待用户指示 |

## 边界

- 本技能只修"格式错误导致未执行"；不修其他原因的卡死（权限、参数语义、模型策略）；
- 技能无 host 代执行能力：一切调用由模型自己发起，权限/guard 照常生效。
